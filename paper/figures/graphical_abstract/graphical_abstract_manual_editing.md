# Manually editing the graphical abstract

The draft is one self-contained HTML file:
`paper/figures/graphical_abstract/graphical_abstract.html`
(a plain standalone document — open it directly in a browser, no special viewer needed). It was
committed at version v38 of the design session; check the `<title>` tag inside for whichever
version is currently there if it's been edited since.

Live view (may be ahead of or behind the committed file, depending on which was updated last):
https://claude.ai/code/artifact/943f8add-e44c-4448-8d7c-08fcbf9776a8

## What's safe to edit yourself

- All the **text** you see rendered — headings (`<p class="lbl">...</p>`), captions
  (`<p class="cap-line">...</p>`), the chip labels, the header line — is plain readable text in
  the file. Search for the words you want to change and edit them directly.
- The **CSS** lives in one `<style>` block near the top. Colors are CSS custom properties at the
  very top (`--blue`, `--text`, `--red`, etc.) — change a value there and it updates everywhere
  that color is used, in both light and dark mode (each variable has a light-mode value under
  `:root` and a dark-mode value under `:root[data-theme="dark"]`).
- Layout is built from a small set of reused classes rather than one-off styles per element:
  - `.frame` — the bordered outer box shared by all three top-level sections (single simulation
    / multiple simulations / application). All three currently share the same blue border; a
    section only needs its own rule if it should ever differ again.
  - `.box` — the bordered card look shared by the Pre/Exec/Post-processing columns.
  - `.app-group`, `.combine-group` — the equal-width card layout shared by the Application and
    Multiple-simulations rows (one shared CSS rule, two class names in the markup).
  - `.lbl` — every card/column header (blue, normal case). `.cap-line` — every caption line
    underneath an image or icon.
  - If you want to change how *all* headers or *all* captions look, edit the one shared rule
    rather than hunting for each instance.

## What NOT to touch

- Anything starting with `data:image/png;base64,` or `data:image/svg+xml;base64,` — that's an
  embedded image, a wall of random-looking characters. Don't edit inside it; if you need a
  different image, it has to be re-exported and re-embedded (ask for that rather than
  hand-editing).

## After editing

- To preview: just open the file directly in a browser (`file://` URL) — it's a normal
  standalone HTML page.
- To update the shared Artifact link above to match your edits, it needs to be re-published
  there explicitly — ask for that (or do it yourself if you have Artifact-publish access).
  Editing this repo file alone does not push anything to the shared link, and vice versa:
  republishing the Artifact doesn't update this repo file automatically either. Keep them in
  sync deliberately.
- Where the real plots come from: every plot thumbnail in the page is generated by
  `paper/figures/generate_graphical_abstract_assets.py` from one consistent example simulation,
  then base64-embedded into the HTML by hand. If a plot itself needs to change (not just its
  caption), that script needs to change and the image needs re-embedding — a text/CSS edit alone
  can't do that.
- Full requirements/design-decision history: see `graphical_abstract_requirements.md` in this
  same folder.
